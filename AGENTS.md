# Agent Instructions

1. Read `DEV_SKELETON.md` before planning repository changes.
2. Read `REVIEW_SKELETON.md` before reviewing code or changing behavior with meaningful user, data, or model impact.
3. Treat both skeletons as orientation only. Inspect the current source, configuration, and diff before making implementation claims.
4. Keep changes scoped to the request and preserve the durable constraints unless the user explicitly changes them.
5. Update the skeletons only when a durable project boundary changes. Routine implementation work should not modify them.
6. Do not add function catalogs, architecture mirrors, generated source indexes, or transient behavior notes to these files.
7. The repository owns only the three skeleton documents. Use the externally maintained `skeleton-refresh` workflow when available; do not vendor its skill files or introduce VASMC solely to maintain this skeleton.
